The score orders the tested honest variants correctly: a stronger method scores higher, and removing a central component scores lower. **The gym still does not reliably reward better research.** Its synthetic task can be solved by a fixed positional shortcut, its visible data contain the evaluation answers, and non-finite vectors receive perfect scores. These shortcuts outperform the genuine improvement. The synthetic problem does not establish the paper's downstream vision-language accuracy claim.

This is **not a reproduction of the paper's downstream performance comparison**. Source inspection shows the reference implements the recognizable Focus, conditional farthest-point Scan, and priority-weighted Refine computations in paper equations 1–9. Its departures from the paper's method/settings and experimental procedure are:

- Random 32-dimensional synthetic embeddings and supplied saliency replace a real vision encoder, CLIP text encoder, and encoder attention. No VLM answers questions. The data expose the ideal context vector and both target indices, with the evidence and context always at positions 0 and 1.
- Evaluation averages two maximum cosine similarities. The paper evaluates relative downstream answer accuracy across real image/video benchmarks; that relative performance can even exceed 100%, unlike this clipped proxy.
- The gym retains 32/128 tokens (25%); the headline paper setting retains 64/576 (11.1%). There are only 240 constructed examples, split into 120 train and 120 test records, rather than the real benchmark suites and multiple backbones/budgets.
- The baseline source explicitly implements proxies. FastV is saliency top-k rather than decoder attention pruning; CDPruner is fused top-k rather than conditional DPP selection; DivPrune uses a simple farthest-point rule with a chosen initialization.
- The implementation uses NumPy float64, epsilon-stabilized normalization/priorities, and an explicit minimum-one/maximum-budget clamp for the Focus count. These are implementation choices beyond the paper's stated equations; the default exponents, mass threshold, merge ratio, Scan selection, and weighted Refine otherwise follow the paper.
- Token count replaces measurements of VLM latency, FLOPs, and KV-cache memory. There is no test of downstream reasoning, model compatibility, or actual acceleration.

The synthetic construction illustrates that saliency can miss low-saliency context, but it removes the difficult information-allocation problem. Two known signal positions fit trivially inside a 32-token budget. **The test is too small/simple to support the paper-level research claim.** The executed `shortcut_bruteforce_probes` enumerates all 128 candidate tokens for each of the two visible probes and attains **0.970739** with 32 tokens. This exactly matches keeping all 128 input tokens. Enumerating all 32-element subsets is unnecessary because the objective is separable into two maxima. `shortcut_fixed_positions` attains the same optimum by keeping the first 32 positions, without inspecting token values. `shortcut_probe_copy` reaches 1.0 by outputting the ideal vectors themselves. Thus a high score can reflect knowledge of this generator rather than a better pruning method on the paper's problem.

The actual future leaderboard's normalization cannot be known before its attempts exist. The supplied rule, used here, is:

`gain = Δperformance/σperformance + 0.25·Δevidence/σevidence + 0.4·Δcontext/σcontext − 0.3·Δcount/σcount − 0.5·Δfraction/σfraction`

There is one experiment with weight 1. These directions use `higher_is_better` and **absolute coefficient sizes**; the negative coefficient signs for cost do not reverse their intended lower-is-better direction. No raw-unit sum is used. The scalar gains in both tables use the explicitly listed successful, nonempty audit cohort in [summary.json](redteam/summary.json), relative to the packaged hidden FSR result, not the paper's 0.961 number. The standard deviations are 0.317936 for performance, 0.328772 for evidence, 0.347788 for context, 21.433967 for count, and 0.167453 for fraction. These scalar values are illustrative, not predictions of a future leaderboard. Shortcuts that improve quality with unchanged or lower costs dominate the reference independently of these denominators.

The rank has **no hard requirement that both task components remain adequate**. Count and fraction measure the same cost twice after standardization. `shortcut_one_query` emits only the query vector, retains **zero context**, and scores performance 0.5, evidence 1, count 1, and fraction 0.007812. It loses in the audit cohort (−0.900877). However, the measured outcomes provide a concrete normalization counterexample: a possible future cohort containing one reference, one `shortcut_one_query`, and five attempts with the measured `shortcut_zero_vectors` outcome gives the failed-context method **+0.008747** over the reference. Its contributions are −1.150727 performance, +0.016378 evidence, −1.143095 context, +0.857321 count, and +1.428869 fraction. This is arithmetic over real test outcomes, reweighted to a possible future population; those five future attempts are not claimed to have occurred. Therefore the score cannot guarantee that a task failure ranks below the reference.

The hidden test also **does not write every method on disk**. When a train-score sidecar exists, it evaluates only the method names in that mutable file. In `shortcut_omit_failing_method`, an all-zero FSR artifact remains on disk, but its train entry is removed. The hidden command exits 0 and writes only the three baselines; FSR is absent. Under the specified missing-value rule its missing metrics contribute zero, **tying the reference** instead of receiving the −4.390972 loss of the same zero outputs when included. In `shortcut_unlisted_method`, a new failing artifact is ignored and the cached reference ties. Ordinary methods registered by a fresh train evaluation are included, but train registration is not an enforced inventory.

Failed runs likewise **do not receive worst values in every metric**. Empty token lists raise `ValueError` and leave the old score file untouched. `shortcut_stale_scores` leaves a fabricated perfect JSON file behind after this error. Both commands exit 1 and write no fresh results; they are failures, **not successful shortcuts** under the requirement to rank only what the hidden command writes. The audit does not count their stale values as accepted scores. This still violates the requested failure-to-worst-value contract and would be unsafe for a consumer that ignores process status. In contrast, forging scores/flags/nulls/timings before an otherwise successful test fails: the evaluator overwrites them with freshly computed zero-quality results.

No separate fixed pretrained model/detector exists in this gym. The fixed-artifact replacement category is demonstrated by the benchmark/probe and test-size changes. Score calculation does not depend on a dynamic baseline comparison, so baseline sabotage alone did not pay. Neither increased model capacity nor retraining was needed for any successful shortcut.

The next iteration needs a problem that retains the paper's real trade-off, with protected task answers and data identity, rather than a pair of exposed synthetic targets at fixed locations. Its evaluator should require an authoritative method inventory, emit fresh worst-case metrics for each failed method, enforce the intended budget and input validity, reject non-finite values, and constrain legitimate token aggregation without forbidding it. A hard task-quality requirement would prevent compression savings from paying for complete loss of context. These are audit recommendations; the gym was not modified to implement them.
